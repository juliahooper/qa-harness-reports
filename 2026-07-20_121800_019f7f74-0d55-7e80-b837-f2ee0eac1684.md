## Key Friction Points

- **Operation ID discovery gap**: Agent struggled to find operation IDs, trying multiple command variations (`apis show --api`, `inspect` without operation_id, `endpoints`, `operations`) before discovering the correct path. The `apis operations` subcommand wasn't intuitive from the help hierarchy.
- **Version requirement not obvious**: Initial `apis show` command failed because the agent didn't include the version (`jentic-test/test-api` vs `jentic-test/test-api/1.0.0`). Error message was clear, but the requirement wasn't surfaced earlier in discovery.
- **Authentication details invisible**: Agent noted that `"auth":null` appeared in inspect output and that authentication requirements (X-API-Key header) weren't visible in spec/inspect commands, creating uncertainty about what the broker would handle.
- **Flag naming inconsistency**: Agent encountered an "unknown flag: --api" error, suggesting minor inconsistency in flag naming conventions across commands.

## Unlogged Insights

- Agent observed that the approval workflow was "automatic and took ~5 seconds" but this timing/auto-approval behavior wasn't documented as expected behavior

- **[find-credential]** Add a step showing how to list operations with their IDs (e.g., "Use `jentic apis operations <vendor/name/version>` to see available operations and their operation_ids for use with inspect/execute")
- **[find-credential]** Clarify that API references require the full `vendor/name/version` format throughout discovery commands, not just `vendor/name`
- **[jentic-cli-skill]** In section 3 (Find an operation), explicitly mention that `jentic apis operations` returns the `operation_id` needed for inspect/execute, before the search-based workflow
- **[jentic-cli-skill]** In section 4 (Inspect), clarify that authentication/credential details are intentionally not shown in inspect output because the broker handles credential injection transparently
- **[add-to-toolkit]** Add context that approval may be automatic in some environments (e.g., test/demo setups) vs requiring human review in production, so agents understand variable wait times
