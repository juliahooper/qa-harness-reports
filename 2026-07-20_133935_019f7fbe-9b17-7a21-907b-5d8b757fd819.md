## Journey

The agent successfully completed all three onboarding goals in approximately 10 minutes: registered and confirmed identity, discovered the test API using `jentic apis list/show/spec`, requested and received toolkit access with the `--wait` flag, and executed GET requests through the broker using both operation_id and full URL syntax. The flow was largely smooth with minor friction around command discovery and understanding authentication visibility.

## Key Friction Points

- **Command naming confusion**: Initially tried `jentic api list` (singular) before finding the correct `jentic apis list` (plural). Error message did suggest the correct command.
- **API reference format trial-and-error**: First attempt at `jentic apis show` failed because the version component was missing from the reference (`jentic-test/test-api` vs `jentic-test/test-api/1.0.0`).
- **Authentication requirements invisible**: The agent couldn't determine from `apis show`, `apis inspect`, or `apis spec` output that the API required an X-API-Key header. Had to infer authentication was needed from the task context rather than discovering it through inspection.
- **METHOD:/path syntax confusion**: `GET:/get` returned 404 'operation_not_found' from the broker despite help text describing it as "broker-relative." Agent couldn't determine when this syntax should be used versus operation_id or full URL approaches.
- **Admin vs user command exploration**: Briefly explored `jentic access --help` which showed admin commands before finding the user-facing toolkit request flow.

## Unlogged Insights

- Agent systematically explored available commands using `--help` flags when stuck (e.g., `jentic apis --help`, `jentic apis inspect --help`, `jentic access --help`)
- Discovered the `operation_id` value (`getRoot`) by examining the OpenAPI spec output before attempting execution
- Tested multiple execution syntaxes to understand their differences: operation_id (worked), METHOD:/path (404), and full URL (worked)
- Successfully used `jentic access refresh` to activate the newly granted toolkit binding before attempting execution

## Suggested Skill Doc Improvements

- **[find-credential]** Add a note that authentication/security requirements may not be visible in `apis show` or `apis inspect` output, and that the broker will handle credential injection automatically once toolkit access is granted—agents don't need to manually discover auth schemes.
- **[jentic-cli-skill]** In the "Execute through the broker" section (step 5), clarify when the `METHOD:/path` syntax is appropriate versus `METHOD:URL`. The current text mentions it's "broker-relative" but doesn't explain that it requires the broker to resolve the path, which may fail if the operation isn't registered. Consider adding: "The `METHOD:/path` syntax is broker-relative and requires the broker to resolve the path; prefer using `operation_id` from search results or the full `METHOD:URL` for reliability."
- **[jentic-cli-skill]** In the "Find an operation" section (step 3), add a brief note that `jentic apis operations <vendor/name/version>` can be used to list operations for an already-known API without searching, since the agent discovered this command organically but it's not explicitly mentioned in the discovery flow.
