## Journey

The agent successfully completed all three onboarding goals: discovering the test API in the registry, requesting toolkit access, and executing a proxied request through the broker. The agent navigated command inconsistencies and format ambiguities by using help text and the `search` command as fallback discovery tools, ultimately achieving end-to-end execution without requiring human intervention beyond the initial access approval.

## Key Friction Points

- **Command pluralization inconsistency**: Tried `jentic api list` which failed, requiring correction to `jentic apis list` — made command discovery difficult through trial-and-error
- **API reference format confusion**: The `apis list` output displayed "jentic-test/test-api/1.0.0" but `apis show` rejected "jentic-test/test-api" and required the full vendor/name/version format with explicit version
- **Inspect command argument format**: Unclear how to construct the `METHOD:url` format needed for `jentic inspect` from the API listing output — agent had to use `jentic search` as an intermediate discovery step
- **Credential visibility gap**: Attempted `jentic credentials list` (which doesn't exist) because there was no obvious way to directly list available credentials — had to work backwards through toolkits and access requests
- **Authentication field interpretation**: The `inspect` output showed `auth: null` which caused momentary confusion about whether credentials were needed

## Suggested Skill Doc Improvements

- **[jentic-cli-skill]** Add a "Common Command Patterns" section in Quick Reference noting that most commands use plural forms (`apis`, not `api`) to reduce trial-and-error during discovery
- **[jentic-cli-skill]** In the "Find an operation" section (step 3), clarify that `apis show` and `apis operations` require the full `vendor/name/version` format even when `apis list` displays it in that format — add an example showing how to pass the exact string from `list` output
- **[jentic-cli-skill]** In the "Inspect the operation's contract" section (step 4), add an example showing how to construct the `METHOD URL` format from an `apis operations` output row, since this isn't self-evident from the command's response structure
- **[find-credential]** Add guidance that credentials are accessed indirectly through toolkits (not via a `credentials list` command), and that `jentic access whoami` shows which toolkits you're bound to as the primary credential discovery mechanism
- **[jentic-cli-skill]** In the "Inspect" section, clarify that `auth: null` in inspect output means the operation requires authentication but the auth details are managed by the broker (not that auth is optional)
